# Security notes

Scope: a TEST-NETWORK wallet assistant. There is no mainnet configuration in `src/networks.js`.

## Trust boundaries
- **Model output is untrusted.**
  - The LLM gets text in and grammar-constrained JSON out. It has no tools, no files and no network.
  - `src/intent.js` re-validates every field: closed enums, an amount regex, name characters, lengths and a 2 KB output cap.
  - Addresses are never taken from the model; a regex copies whole addresses from the person's own text.
  - Scam flags from the model are filtered to a closed list (prototype keys rejected, tested) and can never lower
    the risk. On their own they never reach "high".
- **Spoken/typed/pasted text is untrusted.**
  - Control, zero-width and bidi characters are stripped, and input is capped at 1-2 k characters.
  - Audio is checked by content (RIFF/WAVE, 16-bit PCM, at most 5 MB, at most 30 s).
- **Screenshots are untrusted** (`src/ocrtext.js`).
  - Checked by content, not by name or declared type: PNG signature or JPEG SOI, at most 4 MB. The pixel size is read
    from the header and refused above 4096 px per side or 12 megapixels, so a decompression bomb never reaches the
    decoder. The bridge also checks the type and the magic bytes; the CLI reads regular files only.
  - QVAC OCR only produces text. That text is cleaned and capped like pasted text and goes through the same checks;
    OCR makes no decision. The only repair is inside a token shaped exactly like an address (0x + 40 characters):
    O/o become 0 and I/l become 1 (hex has none of them). Any other misread fails the EIP-55 checksum (tested).
  - In the engine the OCR model is loaded for one screenshot and unloaded afterwards; uploads are never written to disk.
- **Signing.**
  - The seed is generated by WDK and stored only in `private/wallet.json` (0600, gitignored; the code refuses to read it
    if group/world-readable). It is never printed; a damaged file gives a generic "wallet file corrupted" error that
    quotes nothing from the file.
  - Signing happens offline. A WDK transaction policy denies every write operation except `signTransaction` of the
    exact transfer the person just confirmed (token, recipient, amount, chain id, gas x fee cap). The approval is
    consumed by one signature.
- **Network code** is limited to `bin/netsync.mjs`, `src/broadcast.js` and `src/net/rpc.js`:
  - https only to the allow-listed testnet endpoints (or http to 127.0.0.1 on the devnet);
  - no redirects, 15 s timeouts, no credentials in URLs, and a 1 MB response cap that is enforced while reading
    (the connection is aborted as soon as the cap is passed);
  - before broadcasting, each raw transaction is decoded and compared with its outbox record;
  - `bin/netsync.mjs` refuses to run unless it was started through the sandbox with the outbox lock held, and it
    checks this before loading any third-party package.

## Checks on the person's own words (src/safety.js, src/amount.js, src/contacts.js)
- **The amount must have been said.** Digits inside an address or another hex string never count, digits glued to
  a word do not count, and a lone "one"/"moja" ("the one from church") is not an amount unless a currency word is
  next to it. The UI never offers such digits as "did you mean" amounts.
- **The recipient must have been named.** Only strong keys count: a word of the saved name, a full alias or an
  alias's first word, never a relation, title or filler word ("mama", "shangazi", "fundi"). The words found must
  resolve back to the same contact on their own, so a family name another person shares, or a first name two
  contacts share, does not count. A contact the person taps on the confirmation screen counts.
- **Shillings and M-Pesa block a payment.** The word "USDT" somewhere in the sentence does not lift this: a
  shilling mention is only accepted next to an explicit USDT amount, and then the payment must be that amount.

## Local UI: resident engine + bridge
- **Engine** (`src/engine.js`, started by `bin/serve.mjs`): runs inside the `offline` sandbox and refuses to start
  outside it or when the internet is reachable. `bin/serve.mjs` (and the CLI launcher `bin/sauti.mjs`) checks this
  with Node built-ins BEFORE any third-party package is loaded. The engine listens only on a Unix socket
  (`tmp/run/engine.sock`, mode 0600, directory 0700), handles one request at a time, caps bodies (16 KB JSON,
  5 MB audio) and keeps confirmation sessions for 15 min, once only. Before signing it re-runs the code checks on
  the current state (limits and outbox may have changed). Voice notes left over from a killed engine are deleted
  at the next start.
- **Bridge** (`bin/bridge.mjs`, Node built-ins only): binds 127.0.0.1 and verifies it did.
  - **Per-launch UI key.** `ops/ui.sh` makes a random key (32 bytes) at every start and prints the link
    `http://127.0.0.1:8787/#k=<key>`. The fragment never goes over the network; the page keeps the key in
    `sessionStorage` for that tab, removes it from the address bar and sends it in the `x-sauti-key` header. The
    bridge keeps only a SHA-256 of the key, compares in constant time (`crypto.timingSafeEqual`) and answers every
    API call without the right key with 401. So other users or programs on the same machine that can reach
    127.0.0.1 cannot drive the wallet without the link. The key is never passed into a sandbox and never logged.
  - It rejects other Host headers (DNS rebinding) and other Origins; the key header also forces a CORS preflight
    for any cross-site page, which is never answered.
  - It serves a fixed list of files with fixed content types and forwards a fixed list of routes with validated
    query parameters, bounded bodies, timeouts and one request at a time. Responses carry a strict CSP
    (`default-src 'none'`, scripts only from self) and `frame-ancestors 'none'`.
- The bridge never reads `private/` and the seed never leaves the engine. Responses carry only text, public
  addresses and transaction hashes (tests assert that no raw transaction or seed appears).
- The bridge's only network action is starting the separate, keyless sender with fixed arguments
  (`ops/devnet.sh` or `ops/sandbox.sh online node bin/netsync.mjs`), one job at a time, killed after 240 s.

## Broadcasting without double payments (src/broadcast.js)
- A payment is offered for re-signing ("needs_resign") only when the chain proves this exact transaction can no
  longer be mined: no receipt for its hash, the LATEST (mined) nonce is past its nonce, and the node does not know
  the hash at all. A transaction waiting in the mempool (it counts in the pending nonce only) is never re-signed.
- Network errors never mark a payment "failed": its result is unknown, it stays in the outbox and inside the daily
  limit, and the next run checks it again by hash. A node refusal keeps it queued. "Already known" counts as sent.
- A payment that fell out of the mempool is sent again with the same signed bytes, so at most one can be mined.
- Each sync/broadcast run holds an exclusive `flock` on its outbox directory `queue/<network>/` (the directory
  itself, so there is no lock file to swap for a link): runs from the CLI and from the UI never overlap.

## Undo window: cancel and hold (src/undo.js)
- Only a `queued` payment that was never handed to a node can be cancelled (no `broadcastAt`, `sendTriedAt`,
  `sentToNodeAt`, no node refusal, no "send" claim). The person must confirm (`confirm: true`, CLI `--yes` or a
  prompt). Nothing is signed; the signed bytes are deleted from the outbox after the record was checked against them.
- The send/cancel decision is made once per signature, atomically: `claim-<signId>.json` is created with O_EXCL by
  whichever comes first, the broadcaster ("send", right before the bytes go to a node) or the cancel ("cancel").
  The broadcaster also re-reads every entry from disk right before it handles it. So a cancel and a broadcast at
  the same moment (CLI in two terminals) can never both happen. An unreadable or odd claim file counts as "send"
  (never cancellable). The UI bridge also refuses a cancel while a broadcast job runs.
- Nonces: a cancelled payment's nonce is free again (no gap). Newer queued payments behind it become
  `needs_resign` with their bytes deleted and a "cancel" claim on their old signature; signing one again gives it
  the lowest free nonce. Signatures are deterministic, so a re-signed payment can be byte-identical to its withdrawn
  bytes: that is the same single payment, and claims are keyed by signature id (not hash) so it stays sendable.
- Hold: a payment with a first-time recipient, scam wording, a look-alike warning or a relation that does not match
  is queued with `holdUntil` = now + `hold_minutes` (config.json, 10; 0 = off, max 60). The broadcaster does not
  send it, or anything after it, before that time. The hold is a protective delay on this device's clock, not a
  security boundary.
- Tests: `test/undo.test.js` (incl. a race test that fails with the claim check removed: positive control) and the
  undo-window checks in `test/e2e_ui.mjs` and `test/e2e_offline.sh`.

## Sandboxing (ops/sandbox.sh, bubblewrap)
The project directory is mounted **read-only in every mode**, so code inside a sandbox can never change files that
later run on the host (`bin/`, `ops/`, `scripts/`, `src/`, `ui/`, `.git`). Each mode gets write access only to:

| Mode | Network | Writable | Hidden (empty, read-only) |
|---|---|---|---|
| `offline` (all AI, all signing) | none: own empty network namespace | `private/` `queue/` `tmp/` `home/` | the rest of the system |
| `devnet` (local chain + sender) | private loopback only | `queue/devnet/` `home/` | `private/` `tmp/` other outboxes |
| `online` (testnet sender) | host network | `queue/<network>/` `home/` | `private/` `tmp/` other outboxes |
| `setup` (npm ci, model download) | host network | `node_modules/` `models/` `home/` | `private/` `tmp/` `queue/` |
| `scripts/fetch_registry_model.sh` (OCR weights, once) | own namespace via pasta: internet only (see below) | a fresh staging directory under `tmp/` | `private/` `queue/` `tmp/` `home/` |

- Test runs (`SAUTI_DATA=tmp/<name>`) keep their throwaway wallet under `tmp/<name>/private/`; only `offline`
  mode can see it. A writable directory that is or goes through a symlink is refused.
- Everywhere: only `/usr` and `/etc` (read-only), empty `/tmp`, `/run`, `/home`, `/var`; a cleared environment
  rebuilt from a short allow-list; HOME is the project's own `home/`.
- `online` and `setup` share the host's network namespace, which also means services on the host's 127.0.0.1 are
  reachable from them. That is why they never run third-party package code: `setup` only runs npm (lifecycle
  scripts forced off) and curl; `online` only runs our `bin/netsync.mjs` (plus ethers for decoding) and the probe.
- **The OCR weights** (`OCR_LATIN`, `OCR_CRAFT`) are published by QVAC only in its own peer-to-peer model registry
  (Hyperswarm), not on Hugging Face, so downloading them needs package code with a network: QVAC's
  `@qvac/registry-client` (pinned in the lockfile). `scripts/fetch_registry_model.sh` runs it fenced, once:
  pasta (package `passt`) gives it its own network namespace with outbound internet only (no port forwarding,
  host loopback not mapped), and routes inside refuse 10/8, 172.16/12, 192.168/16, 100.64/10, 169.254/16 and the
  namespace's own subnet and gateway (some hypervisors forward the gateway address back to the host's loopback);
  then bubblewrap with the project read-only, only a fresh staging directory writable, no capabilities (so it cannot
  change those routes). Before downloading, `scripts/registry_fetch.cjs` checks that the `models.json` entry equals
  the SDK's own registry constant (core key, block range, size, sha256; tampered entries are refused, tested); after
  it, size and sha256 are checked again on the host. `scripts/fetch_registry_model.sh --probe PORT` shows the fence:
  on our box the host reached a local service on 127.0.0.1 and via the gateway; the fenced process reached neither,
  nor 10.0.0.1, could not add a route or write project files, and did reach the internet over HTTPS with DNS.
- `scripts/eval_fleurs_asr.sh` (optional evaluation, public speech data) downloads with host curl (https only, a
  pinned dataset commit, size and sha256 checked) into the git-ignored `tmp/fleurs/`. The TSV and the archive are
  parsed as data by `scripts/fleurs_prepare.py` (strict per-field checks; from the archive only regular files with
  whitelisted names, written by basename, size-capped, checked as WAV; tested with traversal, absolute-path, symlink
  and non-WAV members). Speech to text then runs in `offline` mode; the archive and audio are deleted afterwards.
- `ops/local.env` (optional machine-local settings) is parsed, never executed: only `SAUTI_NAME=plain-value` lines
  are read, and the file must be owned by you and not group/world-writable. No sandbox can write to `ops/`.
- Host-side demo helpers keep their browser profile outside the project and check `/proc/<pid>/cmdline` before
  stopping a process group, because `tmp/` is writable from the offline sandbox.
- Isolation is proven with `ops/sandbox_probe.mjs` (host = positive control) and `test/sandbox.sh` (each guard with
  a positive control: the old read-write binding could write `bin/bridge.mjs`, every mode now cannot).

## Supply chain
- Exact pins and a committed lockfile. `--ignore-scripts` is set (no package in the tree has install scripts).
- Tarball sha512 was compared with registry integrity; registry signatures were verified for all 289 lockfile entries
  (`scripts/verify_sigs.mjs`). Reports are in `vetting/`.
- Models are verified by sha256 against QVAC's registry values (`models.json`). The OCR weights also arrive as
  Hypercore blocks, which the registry client verifies against the registry core key.

## Known gaps
- `online` mode shares the host network namespace (see above).
- The devnet anvil state file and the outbox (signed transactions, public once broadcast) are stored unencrypted.
- Processes of the same user can still read the engine socket (file permissions only, 0600), the bridge's memory
  and the link in the terminal's scrollback. The UI key protects against other users and against programs that
  only reach 127.0.0.1; it is not a defence against malware running as you.
- OCR time grows with the number of text regions in an image. A crafted screenshot with very many regions can keep
  the engine busy (one request at a time); the bridge stops waiting after 60 s, but the OCR run itself is not cancelled.
- Single-user, test-network prototype. Not audited.
